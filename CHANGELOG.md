# Changelog

All notable changes to this project are documented here.

## [Unreleased]

- **The web studio asks before it lifts an error, in the eight languages, and the virtual board loads the decisions late:** the text of the confirmation of the clear-error button is in the catalog of the web studio. `virtual_board.py` imports `safety_policy` only when the clear-error command arrives, so a program that copied the virtual board before the decisions existed (and refreshes only the files it already lists) keeps importing it.

- **The Spanish, German, French and European Portuguese README were read sentence by sentence:** calques ("rueda" for a Python wheel, "forgiven" for ignored, "lock"), words of another language and mixed names of the programs (tester, updater, Web Studio) were corrected so that each program is called the same way throughout, and the rate limiter of the serial links is worded as frequency ("cadence" in French) and never as bit rate. The Chinese texts say "flashing" with one word, 刷写 (flash a firmware image, over the bus or with a probe), in the catalogs and in the README, instead of mixing it with 烧录 and 烧写.

- **Two checks of the workflows and of the lessons of past CI failures, both opt in and with a baseline:** `tools/workflow_hygiene.py` reports actions not pinned to a SHA, jobs without `timeout-minutes`, workflows without top-level `permissions`, release workflows without `concurrency`, `pull_request_target` that checks out the pull request and secrets written inside `run:`; `tools/lessons_lint.py` reports `subprocess` calls without a timeout, visible text outside the language catalogue, a coverage floor above the last measured coverage, language keys missing from one of the eight languages and a version that differs between its places. A repository turns them on with `tools/hygiene_config.json` (or a baseline file), and only findings that are not in its baseline fail `ci_validate`; `--write-baseline` saves today's findings, and without either file the step never blocks. Tests included.

- **The comparison with the web studio accepts the reasons only the slave reports:** the list of verify-fail reasons of the web studio must hold the ones of the bootloader and may hold the ones of the expansion slave (not confirmed, digest chunk missing), which the comparison used to reject.

- **Texts for the bus speed selector and for the thermal head status in the web studio catalog:** the "Bus speed" selector (label, "Automatic (listen only)" and its hint), the message for a speed chosen by hand that no head answers, the rewritten no-response message (the bus is only listened to, nothing is sent) and the two reasons of the thermal view (capture error, head not ready), in the eight languages.

- **The four digest chunks of the slave relay have an implicit index:** the identifier 0x212 still carries 8 data bytes and no index byte, but the position of each chunk is now a count that every 0x211 sets to zero, every 0x212 raises by one and the fourth returns to zero, checked when 0x214 arrives. With a group of chunks left half way (1 to 3 counted) the master bridge does not forward the end frame, reports `VERIFY_FAIL` on 0x215 and answers 0x219 with the new reason `DIGEST_CHUNK_MISSING` (7, enum `slave_verify_fail_reason`), so a lost frame says "a digest block was lost" instead of a puzzling signature mismatch; with none (a sender without digest) nothing changes. **Compatibility:** no length changes and a sender of the four chunks in order is unaffected; an older tool shows reason 7 as an unknown reason. The legacy signature chunks 0x7F7 keep their layout (the current bootloader reads the Ed25519 record instead). The specification, the generated modules, the canbus document, the texts of the flasher and the web studio in the eight languages and a test of the rule carry it; not tried on a bus with real boards.

- **A latched critical error can be lifted by command, without a power cycle (switch off by default):** the new identifier `0x1B2` (`CLEAR_ERROR`, the magic payload `CLER`) works only while the feature `CLEAR_ERROR` of `0x1AE` (bit 16) runs. The error is lifted only when the tool is below `CLEAR_ERROR_MAX_TEMP_C` (50 C) and known, and every actuator is at zero; an error for lack of a valid tool is never lifted. The quick state `0x111` grows to eight bytes: byte 6 `error_reason` (why the error was latched: thermal, sensor, tool identity, communication watchdog, fan stall, stepper silence, electromagnet release; the `error_reason` enum) and byte 7 `clear_result` (what the last command did, or why it refused: the `clear_error_result` enum). Both are optional, so a reader of six bytes keeps working and an older board is "not reported", not zero. The mask of `0x1AE` and `0x1AF` reaches seven bits.

- **A communication watchdog for the steppers and a policy for the electromagnet (switches off by default):** the features `COMMS_WATCHDOG` (bit 32) and `MAGNET_RELEASE` (bit 64). With the first on, a stepper move is cut when the board hears nothing for more than `STEPPER_SILENCE_PERCENT` (50) of the time the move should take (steps over speed) and never for less than `STEPPER_SILENCE_MIN_MS` (1000 ms); with both on, the electromagnet lets go after `MAGNET_SILENCE_MS` (5000 ms) of silence; with the second off, it holds, as before. Both latch the critical error with their own reason. `urtc_common.safety_policy` writes the decisions apart from the firmware, `tools/make_safety_vectors.py` writes the shared vectors (`conformance/safety_policy_vectors.json` and `generated/safety_policy_vectors.h`) and the CI checks them; `quick_state` reads the two new bytes, and the virtual board answers the command with the same decisions.

- **Texts of the clear-error command, the new switches and the reasons of an error in the eight languages:** the labels of the three switches, the button, the six outcomes and the eight reasons, in the tester and the web studio catalogs.

- **The nozzle setpoint of the 3D printer head can be sent alone:** the identifier 0x170 has a second layout of 2 bytes (the setpoint only), next to the 6 bytes it always had (setpoint, extruder direction and 24 steps), which stay as they are. The long frame with 0 steps stops the extruder, so the keepalive of a heater that is on while the extruder moves cancelled the move every 150 ms; the short frame sets the setpoint and refreshes the watchdog and leaves the extruder alone. The specification, the generated modules, the documents and the shared vectors carry both layouts.

- **The host of several heads and the text adapter of the virtual board are tested at their edges:** every reason why a head is not commanded and every way a selection lapses, a selection that is suspended or released, the short status query, every command that is not allowed in the state of the channel, a stream cut in pieces of any size and a stream of noise that never raises and never grows without limit.

- **A line that is not text is answered with a bell and its terminator by the virtual board:** it was answered with a bell alone, which joined the next reply in the stream; the other refusals already ended with the terminator.

- **A reusable workflow to skip expensive jobs on changes that cannot affect them:** `changed-paths.yml` takes globs (and an optional pull request label that forces the answer) and tells a caller, with `matched` and `reason`, whether a change touches them; it reads two commits with a sparse checkout, asks for `contents: read` only, and answers `true` whenever it cannot find what the change is compared with. `test-changed-paths.yml` tries its rules on throw-away repositories (a pull request that touches the paths and one that does not, the label, a push, a manual run, the patterns) and makes one real call. No workflow of the family calls it yet.

- **The workflows have a time limit and a concurrency group:** the CI jobs (baseline and Windows), the dashboard notice and the nightly comparison gained `timeout-minutes`, and the workflows that lacked one gained a `concurrency` group (a newer run cancels an older one of the same branch except on `main`; the nightly run and the dashboard notice are never cancelled).

- **The text of the declared bus speed for the web studio uses the placeholder of that program:** `bushealth.rate_declared` writes `{{rate}}` like the other texts of the web studio, so the page shows the speed instead of the marker, in the eight languages.

- **The heads declare the bit rate of their bus (protocol version 2):** the identity frame `0x1BB` now carries a bit rate code in byte 5 (0 not declared, 1 is 1 Mbit/s, 2 is 500 kbit/s, 3 is 250 kbit/s, 4 is 125 kbit/s; the `bus_rate_code` enum and the `BUS_RATE_*` constants) and keeps the uptime in the last two bytes, which stop at 65535 s instead of wrapping. `protocol_version` of the specification is 2. **Compatibility:** a frame of version 1 is read as before (its byte 5 is still the top byte of the uptime and its rate is unknown), a reader of version 1 only shows a wrong uptime for a frame of version 2, and the symptom judgement stays as the fallback for a head that declares nothing. `urtc_common.health_info` reads both versions (`parse`, `encode`, `declared_rates`, `rates_by_head`, `rate_text`), `bus_health.warnings` takes the declared rates and gives the new first code `rates_declared_differ` when two heads of one bus declare different rates, `HealthTap.take_info()` keeps the identity frames that go by, and `can_timing.declared_rate_warning` uses the declared rates and falls back on the rates the tool knows. Tested with fixed vectors shared with the TypeScript copy, random frames with a fixed seed and the example of the specification; the declaration has not been tried on a bus with real heads.

- **Texts for the declared bus speed in the eight languages:** the tester, the flasher and the web studio catalogs have the warning for heads that declare different speeds, the line that shows the speed a head declares and the line for a head that declares nothing.

- **The text of the held-back power change says it also asks when the power goes down:** `QTLOG_PANEL_POWER_RAISE_BLOCKED` no longer says "raise" in any of the eight languages, and the Italian texts of the web studio use "frame" everywhere, the word the rest of the catalog and the glossary already use.

- **The texts of the Control tab of the web studio say that it sends to the real bus:** the label "Real bus", its hint and the notice of the tab are written in the eight languages for the Control tab that sends to a connected board without a switch, and the hint tells that a drill or a laser that is on asks again for a change of power over the percentage of the configuration file.

- **The image header is tested over every bit and over random input:** no single bit of a sealed image can change without being refused, random bytes never raise nor pass for an image, the version a caller expects may have three or four components, the hardware is compared exactly and before the version, a slot with a signature flag or a reserved byte is not the slot of the firmware, and strange settings of the compatibility switch never loosen it.

## [0.2.6] - Bus at 1 Mbit/s, image header, signed packages and catalogs in 8 languages

- **The register of the eight languages is tested over the whole catalog:** German and French keep the formal form, Portuguese the third person, Spanish no usted, Chinese no 您, every text has the same placeholders as the English one and no text is empty or missing in any of the eight languages.

- **The bit timing and the bus-health judgement are tested over generated inputs with a fixed seed:** every timing that is found is exact and inside the limits of the controller, the search does not depend on the order of the calls, the tolerance never falls with a wider resynchronisation, impossible inputs give no timing, the warning codes are always known, unique and in order, more errors never remove a warning, any configuration gives thresholds inside the limits, and the tap over a bus keeps only the health frames and never more than it was asked to.

- **A bus that mixes speeds is recognised by its symptoms:** `urtc_common.bus_health` turns what can be seen (the error counters and bus-off of the health frames `0x1B8` of the heads that are heard, a search at every speed that finds nobody, a head known to be built for 500 kbit/s) into warning codes, with thresholds read from the configuration file of each tool; no change of the protocol, because a head at another speed cannot be heard and so cannot state its speed. Tested with the virtual bus.

- **The default bit rate of the bus of the tool heads is 1 Mbit/s:** `BITRATE` of `spec/can_protocol.json` is 1,000,000 bit/s, `BITRATE_LEGACY` keeps 500 kbit/s for early boards, the wanted sample point (875 per mille), its floor (750) and the jump width are constants of the specification, and the SLCAN default code is 8 (1 Mbit/s). `urtc_common.can_timing` is the Python reference of the timing the firmware calculates (exact rate, sample point not below the floor), with the table for the clocks of the chips, the limits of the cable at each rate, and the warning for a bus whose heads state different rates. The virtual SLCAN adapter can sit on a bus of a given speed (`bus_bitrate_code`): an adapter set to another speed reaches nobody and hears nothing, so the start-up with a wrong speed is tested without a board. **Compatibility note:** all boards and adapters of one bus must run at the same speed; at 1 Mbit/s keep the trunk under about 25 m with short stubs and a 120 ohm termination at each end.

- **The shared document policy check is refreshed:** `tools/_doc_policy.py` and `tools/ci_validate.py` are the current copies, which also fail when a build script changes a version and when a script switches into a virtual environment instead of running its python directly. The build script only reads the project version (raise it with `bump_version.py`), and the build and run scripts run the python of the virtual environment directly.

- **The package tool can sign a package that was packed somewhere else:** `tools/make_update_package.py sign PACKAGE` signs the very bytes of a `.zip` or `.tar.gz` made by the Windows build in Actions (which holds no key), after checking that the `app_info.json` inside says the app, version and platform of the file name, and writes `PACKAGE.sha256` and `PACKAGE.sig` next to it with the same bytes the `build` command writes. It refuses a key that is not the one the programs trust and runs the same check as `verify` before it reports success, so the three files of a release (package, checksum, signature) can be made and checked in one step without the package being rewritten. Tested for both archive formats, for a name that disagrees with the content and for files that are not packages.

- **The header can be INSIDE the flashed image:** a 32-byte slot at the fixed offset `0x200` (after the vector table, so the flash map, the vector table and the length of the image do not change), flag bit 1, the length of the whole image and the CRC-32 of the image with the header taken as zeros; `URTC_IMAGE_EMBED_SLOT` and `urtc_image_verify_embedded` in C, `embedded_slot`, `seal_embedded` and `verify_embedded` in Python, the new statuses `bad_flags` and `not_sealed`, and `docs/IMAGE_HEADER.md` rewritten.
- **One decision for every tool that reads a file to flash:** `inspect_image` with the compatibility switch `accept`, `warn` (the default) or `require` a header; a header that is there is always checked, a stamped `.urimg` file is never flashed and an unknown value means `require`.
- **`tools/stamp_image.py seal` is the post-build step of the header inside the image**, and `check` tells the two forms apart and applies the switch (`--policy`).
- **Shared vectors for the embedded form:** `conformance/image_header_embedded_vectors.json` and `generated/image_header_embedded_vectors.h` (21 images each way, 17 decisions of the switch), held by the Python reference and by the C header under the sanitizers.

- **Self-update from a signed package (`self_update.py`):** the whole flow of a program that updates itself from a GitHub release, with no network and no window of its own (the caller passes the fetch and the progress callback) and standard library only. `find_update` offers only a strictly higher version (three or four components) that has a package for the platform, never a draft or a pre-release; `download_package` takes the package, its `.sha256` and its `.sig` only over https from the hosts of GitHub release downloads, checks the announced size and the SHA-256, and leaves no partial file behind when it fails; `verify_package` checks the Ed25519 signature of `urtc-pkg/1|app|version|platform|sha256|size` against the key pinned in the program and the key identifier the release declares; `safe_extract` reads a `.zip` or `.tar.gz` without ever writing outside the folder (no `..`, absolute path, drive letter, link or device) and within limits of size and file count; `install_package` refuses while a bus operation is running, checks the `app_info.json` of the package against what was announced, switches `current.txt` and keeps the two latest releases; `rollback` and `finish_first_start` go back to the previous release, the second by itself when the first start of the new one fails; every step is appended to `history.jsonl`. The Ed25519 check is tested against the RFC 8032 vector and the whole flow against a fake server (32 tests); `vendor_copy.py --set update` copies it. No program uses it yet.
- **A floor under the coverage:** the tests run with `--cov=urtc_common` and fail below 77 percent, eight points under the 85 measured (`fail_under` in `pyproject.toml`); the development extras install `pytest-cov` and `pyserial`.

## [0.0.1] - The CAN protocol as data

- **Specification:** `spec/can_protocol.json` (format 1, with its JSON Schema) describes all 88 identifiers of the tool-head bus: direction, who handles each, the tools it is valid for, the length rule and the typed layout of every request and response, the gates (critical error, boot sequence, magic payload), the watchdog and telemetry timing, 16 enumerations, 37 constants, the four magic payloads, the 23 registers of the expansion slave, the version procedures and the SLCAN subset. Every entry records which of the firmware, URTC-FLASHER, URTC-TESTER and URTC-WEB-STUDIO define it, so the gaps are explicit: `0x220`, `0x221`, `0x1A8` and `0x1A9` exist in the firmware and in no host (the last two are not in the protocol prose either), and `0x220`/`0x221` carry a note about the missing allow-list.
- **Generated code:** `tools/generate_constants.py` writes a C header, a TypeScript module and a Python module from the specification, with the constants, the tables and one pure builder and one pure parser per layout, and `docs/PROTOCOL_TABLE.md`. `--check` writes nothing and fails when a file is out of date. Builders refuse an out-of-range value, a value outside a closed enumeration and a wrong magic payload instead of clamping them; parsers report a byte that older firmware does not send as absent, never as zero.
- **Conformance vectors:** `conformance/can_vectors.json` keeps the nine sections that the flasher, the tester and the web studio already share, unchanged, and adds an encode and a decode vector for every layout, the legacy short forms, the encodes that must be refused, the full identifier list and SLCAN byte streams (extended frames, remote frames, glued status characters, noise, a split line). `tools/make_conformance.py` writes them with a packer of its own, independent of the generated encoder, and checks the hand-written example bytes of the specification against it.
- **Python package:** `urtc_common` holds the SLCAN codec (strict hexadecimal, standard data frames only), a classic-frame type, the version and quick-state readers, a runner for the vectors and a small command line. The transports (SLCAN serial, SocketCAN, python-can and a simulated board, plus listen-only bitrate detection) are extracted from the two copies the flasher and the tester kept and merged so that each fix of either copy applies once; they take their serial port, socket and python-can module as parameters, so they are tested with fakes.
- **Comparison with the other repositories:** `tests/test_siblings.py` reads the text of the firmware, the flasher, the tester and the web studio, when they are checked out next to this repository, and fails when an identifier, a magic payload, a tool or status table, a length check, a gate, a limit, a register or the list of identifiers of the protocol prose stops agreeing with the specification. It skips when they are absent: nothing depends on those repositories.
- **Copies for other repositories:** `tools/vendor_copy.py` copies chosen parts into another repository with a lock file of SHA-256 sums, and its `check` fails when a copy was edited by hand or fell behind. Nothing in the other repositories uses it yet; `docs/MIGRATION.md` lists the order in which each can.
- **Documents:** `docs/CONTRACTS.md` (the contract, who implements what, the known gaps and differences, the rules for change), `docs/SPEC_FORMAT.md`, `docs/MIGRATION.md` and the generated `docs/PROTOCOL_TABLE.md`; the README in eight languages.
- **CI:** the baseline workflow runs the shared validation, the generator checks and the tests on Linux and Windows; a nightly workflow runs the comparison with every repository of the ecosystem fetched next to this one.
